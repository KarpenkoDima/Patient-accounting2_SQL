# Известные проблемы

Документ фиксирует причины, по которым репозиторий имеет статус архива.
Это не roadmap и не обязательство исправить перечисленные недостатки.

## Критические

- база не разворачивается с нуля одной подтверждённой командой;
- отсутствует SQL Database Project (`.sqlproj`) и автоматическая проверка схемы;
- в процедурах фильтрации список идентификаторов вставляется в динамический SQL;
- встречается `ROLLBACK TRANSACTION` без гарантии, что процедура открыла транзакцию;
- сохранение связанных частей пациента может быть неатомарным;
- `uspLogError` зависит от отсутствующей в репозитории таблицы `dbo.ErrorLog`;
- выдаются права ролям, создание которых в репозитории не найдено.

## Схема и поддерживаемость

- применяются устаревшие типы, включая `ntext`;
- используются `@@IDENTITY`, старый `@@ERROR` и `RAISERROR`-шаблон;
- отсутствует оформленная стратегия вторичных индексов;
- присутствуют жёстко заданные значения внешних ключей по умолчанию;
- некоторые каскадные удаления потенциально опасны;
- naming содержит неоднозначные имена и опечатки;
- часть constraints могла быть создана как недоверенная через `WITH NOCHECK`.

## EF Core-документация

- примеры не связаны с компилируемым sample-проектом;
- baseline migrations для существующей БД описаны недостаточно безопасно;
- встречаются спорные или неполные примеры domain events и outbox;
- стратегия хранения ключей Data Protection не определена;
- некоторые рекомендации представлены как универсальные, хотя зависят от контекста;
- документы ориентированы преимущественно на EF Core 8 и сохранены только исторически.

## Решение

Исправлять архив точечно не рекомендуется. При возвращении к предметной области следует
создать новый проект и переносить только проверенные таблицы, запросы и бизнес-правила.
