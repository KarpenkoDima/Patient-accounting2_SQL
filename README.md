# Dispancer: Система учета пациентов (SQL Backend)

Комплексная система управления базой данных для медицинского диспансера, реализованная на языке T-SQL (MS SQL Server). Проект охватывает полный цикл управления данными: от проектирования нормализованной схемы до реализации сложной бизнес-логики на уровне хранимых процедур и триггеров.

## 🚀 Ключевые особенности и технические решения

### 1. Архитектура данных и целостность

* **Глубокая нормализация**: База данных спроектирована с учетом минимизации избыточности, включая таблицы для пациентов, адресов, медицинских регистраций, категорий инвалидности и льгот.
* **Сложные связи**: Реализована связь «многие-ко многим» (например, между инвалидностью и категориями льгот через таблицу `Invalid_BenefitsCategory`).
* **Каскадные операции**: Настроено автоматическое обновление и удаление связанных записей для поддержания ссылочной целостности.

### 2. Продвинутая бизнес-логика

* **Механизм Soft Delete (Мягкое удаление)**: Вместо физического удаления данных пациентов используется триггер `INSTEAD OF DELETE`, который устанавливает флаг `Delete = 1`, сохраняя историю для аудита.
* **Управление транзакциями**: Все процедуры модификации данных (Insert/Update/Delete) обернуты в блоки `BEGIN TRANSACTION` / `ROLLBACK` / `COMMIT`, что гарантирует атомарность операций даже при возникновении ошибок.
* **Динамическая фильтрация**: Реализованы процедуры с использованием динамического SQL (например, `sp_executesql`) для гибкой фильтрации записей по спискам идентификаторов участков.

### 3. Безопасность и мониторинг

* **Разграничение прав доступа**: Применяется ролевая модель доступа (`Sensitive_low`, `Sensitive_medium`, `Sensitive_high`) с явным назначением прав `GRANT EXECUTE` и `GRANT SELECT` на объекты БД.
* **Система логирования ошибок**: Разработана централизованная инфраструктура для захвата и хранения информации об исключениях в таблице `ErrorLog`.
* **Абстракция через представления**: Доступ к данным реализован через `VIEW`, что позволяет скрывать сложность запросов и обеспечивать дополнительный слой безопасности.

## 📊 Структура базы данных

### Основные сущности:

* **Customer**: Личные данные пациентов.
* **Address**: Географическая привязка и адреса проживания.
* **Register**: История постановки на учет, снятия с учета и диагнозы.
* **Invalid**: Учет групп инвалидности и периодов дееспособности.
* **Справочники**: Участки (`Land`), типы учета (`RegisterType`), группы инвалидности (`DisabilityGroup`) и др.

## 🛠 Технологический стек

* **Язык**: T-SQL
* **Платформа**: Microsoft SQL Server
* **Инструментарий**: Хранимые процедуры, Триггеры, Представления, Пользовательские типы данных.

## 📂 Примеры реализации

### Процедура сохранения данных пациента

Демонстрирует использование логики «Insert or Update» (Upsert), автоматическое управление датами модификации и вызов вложенных процедур для сохранения примечаний.

### Поиск по сложным критериям

Реализованы механизмы поиска пациентов по фамилии (с поддержкой `LIKE`), адресу, участку и дате рождения с использованием различных предикатов (`>`, `=`, `МЕЖДУ`).
